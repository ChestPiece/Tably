# ChestBest QR Ordering — rebuild plan

## Context

`chestbest-demo` is a sales demo generated by OpenAI's site builder: vinext (beta Next.js clone) on Cloudflare Workers + D1, the whole restaurant stored as one JSON row, 2-second polling, no staff login, static `/?table=N` QR links, and all three views (guest / kitchen / owner) minified into one 44 KB file (`app/restaurant.tsx`). Hosted, it is owner-private, so real guests hit a sign-in wall.

Goal: a fully working, demo-ready dine-in ordering app on **Next.js + Supabase, deployed to Vercel**. Flow: guest scans table QR → sees restaurant + table → enters name (optional) → browses menu → orders → staff are notified live → staff move ticket through preparation → guest sees status → guest calls waiter / requests bill → staff record payment and close the table. In development, everything works without scanning.

Decisions from the 10 questions:
| # | Decision |
|---|---|
| 1 | Fully working for one restaurant now. Data model is tenant-ready (`restaurant_id` on every row) so self-serve restaurant sign-up can come later. |
| 2 | Rebuild on standard Next.js (App Router) + Supabase (Postgres, Auth, Realtime, Storage, RLS). Deploy on Vercel. |
| 3 | Orders always auto-accept. |
| 4 | Anti-fake = best-practice bundle (below), no extra step for honest guests. |
| 5 | Guest name optional (fallback "Guest 1", "Guest 2"…). |
| 6 | One shared visit per table; each phone has its own cart and sends its own ticket with its name; everyone sees the whole table's orders and one bill. |
| 7 | Pay staff in person; guest taps "Request bill"; staff record cash/card and close the table. No gateway. |
| 8 | Live staff board + sound only (demo). Push/printer/WhatsApp later. |
| 9 | Roles: owner (everything) and staff (board, calls, tables/bills). Email login; owner invites staff. |
| 10 | Keep ChestBest brand, English + Arabic (RTL), AED. Fresh art direction, not template look. |

**Anti-fake bundle (Q4):** unguessable per-table QR slug (`/t/k3f9x2`, not `?table=6`); visit ends when staff close the table, so an old photo starts an empty new visit; guests are Supabase anonymous users (rate-limited by Supabase, Turnstile captcha ready to switch on); per-guest order rate limit inside the order function; ticket shows guest name and a **"New table"** badge on a visit's first order so staff can spot a stranger and cancel; optional table PIN per restaurant setting, off by default.

## Approach

### Repo handling
1. With user's OK: commit the current uncommitted demo to branch `legacy-sites-demo` (preserves history), then work on `feat/supabase-rebuild`.
2. Remove OpenAI Sites scaffolding: `vinext`, `worker/`, `.openai/`, `scripts/`, `wrangler`, `drizzle/`, `db/`, `dist/`, `outputs/`, `.sites-runtime/`, `.wrangler/`, `app/chatgpt-auth.ts`, `lib/connector*`.
3. **Reuse**: `components/ui/*` (shadcn — keep only what is used), `lib/utils.ts` (`cn`), seed menu + bilingual copy from `lib/model.ts` `initialState()`, validation rules from `lib/actions.ts` (`applyAction` order/status/settle/close rules port into SQL functions), `money()` fils formatter, test scenarios from `tests/core.test.mjs` (AED 81 sample order, idempotent retry, closed visit rejects, settle-before-close).

### Data model (Supabase Postgres, all money as integer fils)
- `restaurants` (slug, name/name_ar, tagline/_ar, currency 'AED', accent, service_mode table|counter, ordering_paused, pin_required)
- `staff_members` (restaurant_id, user_id → auth.users, role owner|staff)
- `categories`, `menu_items` (price_fils, image_url, available, badge, position), `item_options` (price_fils)
- `tables` (number, qr_slug unique random, pin nullable)
- `visits` (table_id, opened_at, closed_at, bill_requested_at, paid_at, payment_method, settled_total_fils) — partial unique index: one open visit per table
- `visit_guests` (visit_id, user_id = anonymous auth uid, display_name nullable, seq for "Guest N")
- `orders` (visit_id, guest_id, request_id unique per guest, status received|preparing|ready|served|cancelled, total_fils, note, cancel_reason, is_first_of_visit, timestamps per status)
- `order_lines` (snapshots: name, name_ar, option name/ar, unit_price_fils, quantity)
- `service_requests` (visit_id, guest_id, kind waiter|bill, created_at, resolved_at, resolved_by)

### Write path = Postgres functions (security definer, validated)
Guest: `join_table(slug, name, pin?)`, `place_order(request_id, lines[{item,option,qty,expected_price}], note)` (server prices, idempotent, rejects paused/closed/paid/unavailable/price-changed — same codes as today), `call_waiter()`, `request_bill()`.
Staff: `advance_order(id, expected_status)`, `cancel_order(id, reason)`, `resolve_request(id)`, `record_payment(visit, method)`, `close_visit(visit)`.
Reads via RLS: guests read menu of their restaurant + orders of their own visit only; staff read their restaurant only.

### Realtime + sound
Staff board and guest tracker subscribe to Supabase Realtime `postgres_changes` (RLS-filtered) on `orders` and `service_requests`; refetch on reconnect and on `visibilitychange`. Staff board has a "Start shift" button (unlocks Web Audio for chime — browsers block autoplay), uses Wake Lock to keep the tablet awake, flashes tab title on new order/call.

### Routes
- **Guest**: `/t/[slug]` welcome (brand, table no., name field, PIN if on) → `/t/[slug]/menu` (categories, search, item sheet with options, cart drawer, sticky bottom bar) → order tracker (live status timeline), table bill (all orders by guest name, total), Call waiter, Request bill. Visit-closed and ordering-paused states.
- **Staff** (`/staff`, Supabase Auth login): live board in columns Received / Preparing / Ready with age timers, served history, calls & bill requests panel, tables view (open visits, bill, cash/card, close).
- **Owner** (`/admin`): menu (categories, items, options, availability, photo upload to Storage), tables (add/remove, regenerate slug, printable QR sheet with table number + brand), settings (brand, colors, pause ordering, service mode, PIN toggle), staff invites, today's numbers.
- **Dev only** `/dev` (404 in production): list of tables with direct guest links, one-click sign-in as seeded owner and staff, reset demo data. Satisfies "use the app without scanning".

### Language
EN/AR typed dictionary, language in cookie, `dir="rtl"` on `<html>`, logical CSS properties (`ms-/me-`). Arabic menu fields already in seed.

### UI direction
Guest: warm "grill-house printed menu" — cream paper background, charcoal type, ember orange accent (existing `#e85d2a`), big real food photos, one confident display face + readable text face (Latin + Arabic pair), thumb-zone bottom actions, mobile-first. Staff: dark high-contrast tablet board, large type, colour-by-age timers, no decoration. Owner: plain, dense, functional. Gate every screen with anti-slop review (no gradient blobs, emoji labels, glow, uppercase eyebrow everywhere — the current copy has many "eyebrow" taglines to cut).
