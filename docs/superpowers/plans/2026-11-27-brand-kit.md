# Brand Kit (Phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An owner sets logo, brand colour, cover, vibe, welcome note and Instagram, previews it live, and every guest surface and printed QR card wears it, always readable.

**Architecture:** Six new/reused `restaurants` columns. One pure function `brandTokens(hex, vibe)` turns them into CSS custom properties, with an OKLCH contrast guard. The guest app applies them inline on its root (no flash) and on `<html>` (so portalled sheets get them). The owner Brand section edits a draft that drives a phone preview using the real `Welcome`.

**Tech Stack:** Next.js 16, React 19, Tailwind v4 tokens, next/font/google, Supabase (RLS, storage `menu-images`), `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-27-brand-kit-menu-psychology-design.md` (Phase 1 + "Builder check answers").

## Global Constraints
- Run commands with `npm.cmd` (PowerShell blocks `npm.ps1`). Tests: `npm.cmd test` (`node --test "lib/**/*.test.ts"`).
- Git needs `-c safe.directory=*`. Commit only when Anas asks; commit steps below are checkpoints to run once he has said yes. Repo is public: never commit `.env*`.
- Brand applies to guest surfaces (`/t/...`) and `/admin/qr` cards only. Owner and staff UI never change colour.
- Contrast: brand on cream `#F6F3EB` ≥ 3:1; `--on-brand` text on brand ≥ 4.5:1.
- Ochre tokens never follow the brand.
- Every new guest string has EN + AR in `lib/i18n.tsx` (`key: [en, ar]`). Logical CSS only (`ms-`, `me-`, `start`, `end`).
- No template tells (`design.md`): no gradients, glows, emoji labels.
- Migrations applied via Supabase MCP `apply_migration` (project `xyptwnbukercpptbleei`); if declined, Anas runs the SQL in the dashboard. Tests via `execute_sql`.

## Review Focus
1. Arabic guest page on a non-Sufra vibe: Arabic text must render in the vibe's Arabic face, never Arial. (Task 4, manual check in Task 8.)
2. Logo with no colour (black on white, or transparent PNG): no swatches, no crash, hex input still works. (Task 3 test.)
3. Owner types a bad hex (`#fff`, `red`, empty): save blocked with a field error; DB check would reject it anyway. (Task 6.)
4. Opening an item sheet / cart drawer on a branded venue: buttons in portals use the brand colour. (Task 5.)
5. Very light brand (`#FFF5CC`) and neon (`#39FF14`): guest welcome card stays readable. (Task 2 test.)

### Task 2: Token engine `lib/brand.ts`

**Files:**
- Create: `lib/brand.ts`, `lib/brand.test.ts`

**Interfaces:**
- Consumes: `Vibe` from `lib/types.ts`.
- Produces:
  - `export const SUFRA_BRAND = "#1E2A5A"`
  - `export function contrast(a: string, b: string): number` (WCAG ratio of two hex colours)
  - `export function brandTokens(hex: string, vibe: Vibe): Record<\`--${string}\`, string>` — keys: `--primary`, `--ring`, `--brand`, `--on-brand`, `--primary-foreground`, `--brand-field`, `--brand-rule`, `--radius`, `--nf-display`, `--nf-display-ar`, `--font-display`, `--font-sans`. Colour values are `#rrggbb`.
  - `export const VIBES: Record<Vibe, { label: string; radius: string; display: string; displayAr: string }>` where `display` / `displayAr` are `var(--nf-…)` references (filled in Task 4; Task 2 uses Sufra's `var(--nf-display)` / `var(--nf-display-ar)` for every vibe).

- [ ] **Step 1: Write `lib/brand.test.ts`** (`node:test` + `node:assert/strict`, same style as `lib/stats.test.ts`):
  - `contrast("#000000", "#ffffff")` ≈ 21 (within 0.05); `contrast("#F6F3EB", "#F6F3EB")` = 1.
  - For each of `#1E2A5A`, `#FFF5CC` (pale), `#39FF14` (neon), `#E85D2A`, `#000000`, `#FFFFFF`: `t = brandTokens(x, "sufra")`; assert `contrast(t["--brand"], "#F6F3EB") >= 3` and `contrast(t["--on-brand"], t["--brand"]) >= 4.5`; `t["--primary"] === t["--brand"]`, `t["--ring"] === t["--brand"]`, `t["--primary-foreground"] === t["--on-brand"]`.
  - `brandTokens("#1E2A5A", "sufra")["--brand"]` equals `#1e2a5a` (already passes, unchanged).
  - Invalid inputs `"red"`, `"#fff"`, `""` return the same object as `brandTokens(SUFRA_BRAND, "sufra")`.
  - `brandTokens(x, "bold")["--radius"] === VIBES.bold.radius`.
- [ ] **Step 2: `npm.cmd test`.** Expected: FAIL, cannot find module `./brand`.
- [ ] **Step 3: Implement.**
  - Hex ↔ OKLCH with the standard OKLab matrices (Björn Ottosson); convert back with per-channel clamp to [0,1] (gamut clip) before hex.
  - Guard loop: start at input L; while `contrast(brand, cream) < 3` or `max(contrast(cream, brand), contrast(INK, brand)) < 4.5`, lower L by 0.01 (keep hue, chroma). `INK = "#1F2547"` (≈ `--foreground`). `--on-brand` = cream if `contrast(cream, brand) >= 4.5`, else INK.
  - `--brand-field`: brand L +0.06 (dark brand) or −0.06 (light brand, when on-brand is INK), chroma ×0.9. `--brand-rule`: same direction, ±0.18, chroma ×0.8. Matches today's Sufra steps (30.3 → 36 → 48).
  - `--font-display: ${display}, ui-serif, Georgia, serif`, `--font-sans: var(--nf-sans), system-ui, sans-serif`, `--nf-display: ${display}`, `--nf-display-ar: ${displayAr}`. Safe on `<html>`: every descendant re-matches `:where(:lang(ar))` and rebuilds `--font-display` from the overridden `--nf-display-ar`.
  - `VIBES` radii: sufra `12px`, bold `6px`, clean `16px`, classic `4px`.
- [ ] **Step 4: `npm.cmd test`.** Expected: PASS.
